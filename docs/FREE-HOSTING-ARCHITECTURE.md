# Free-hosting architecture for TEa.G3-studio

**Decision:** target a $0/month baseline. Do not depend on paid AI-agent subscriptions, paid model APIs, or paid GPU inference. Free plans are quotas, not an unlimited production guarantee.

## 1. Recommended deployment topology

| Layer | Target | Responsibility | Free-tier caveat |
|---|---|---|---|
| Web frontend (when added) | Cloudflare Pages | Static web client and PWA assets | Static hosting only; it does not run Python or AI models |
| API | Render Free Web Service | FastAPI endpoints, auth, project orchestration | Sleeps after 15 minutes idle; cold start can take about a minute; filesystem is ephemeral |
| Database | Supabase Free Postgres | Accounts, projects, metadata, job records | 500 MB database; free projects may pause after one week of inactivity |
| Media object storage | Cloudflare R2 Standard | Uploaded assets and exported files | Free allowance: 10 GB-month, 1M Class A and 10M Class B operations monthly; overages can cost money |
| CI | GitHub Actions | Tests, linting and builds | Usage is quota-limited by GitHub plan |
| AI planning in phase 1 | Deterministic in-app planner | Turns a brief into a structured edit plan without external model calls | Not a generative LLM; label output as a draft |
| Media rendering in phase 1 | Client-side / Android Media3; FFmpeg where supported | Trim and compose media without cloud GPU | Current Android app only supports single-clip trimming |
| AI image/video generation | Disabled until a genuinely free GPU resource or grant is available | Optional generation adapter | Do not promise always-on free GPU or silently fall back to paid inference |

Official plan details change. Re-check provider limits before each deployment:
- Render free service lifecycle and ephemeral disk: https://render.com/docs/free
- Supabase free plan: https://supabase.com/pricing
- Cloudflare Workers limits: https://developers.cloudflare.com/workers/platform/limits/
- Cloudflare R2 pricing: https://developers.cloudflare.com/r2/pricing/

## 2. Important architecture boundary

The existing FastAPI backend uses SQLite at `backend/data/teag3.db`. That is appropriate for local development only. It must **not** be deployed to a Render free instance because local files are lost on restarts, redeploys, and spin-down.

Before exposing the API publicly:
1. Replace the SQLite-only persistence layer with PostgreSQL (Supabase) using a migration-managed schema.
2. Add authentication and enforce project ownership on every project, asset, plan, and job endpoint.
3. Store media in R2, never in the API container filesystem or database blobs.
4. Use short-lived signed upload/download URLs generated by the backend.
5. Add request size limits, MIME/content validation, rate limits, CORS allowlists, and deletion/retention controls.
6. Add health checks and integration tests against PostgreSQL.
7. Keep all database and R2 secrets server-side in the hosting provider's secret manager. Never commit secrets or expose service-role keys to the browser/mobile app.

Until these steps pass, keep the current backend local-only. The existing README correctly states that it has no authentication.

## 3. AI without paid agents

Do not make Claude, Gemini, ChatGPT, Kimi, DeepSeek, or any other paid API a required runtime dependency.

Use an adapter contract so providers are optional:
- `rule_based`: default, no API key, no subscription, deterministic task planning and validation.
- `local_open_model`: future option for a model hosted on infrastructure we control or a machine the user controls.
- `community_gpu`: optional experimental adapter only when a grant or explicitly free allocation is confirmed.
- `external_paid`: disabled by default and excluded from the $0 baseline; do not enable without explicit user approval.

A free CPU web host is not a substitute for a GPU. Large image/video models should not be installed on Render Free or Cloudflare Workers. If no free GPU is available, generation jobs must report `waiting_for_compute` or `unavailable_free_compute`, not pretend to have generated media.

## 4. Job lifecycle

Persist each task as a database record with:
- `id`, `project_id`, `kind`, `status`, `progress`, `input_json`, `result_json`
- `created_at`, `updated_at`, `error_code`, `error_message`
- `provider`, `model_id`, `billing_mode` (must be `free`, `local`, or explicitly approved)

Allowed statuses:
`queued` → `running` → `succeeded` / `failed` / `cancelled`.
For GPU-dependent tasks, allow `waiting_for_compute` and `unavailable_free_compute`.

Never start a paid operation automatically. Reject unknown providers and any task whose billing mode is not explicitly allowed by the user's settings.

## 5. Phased implementation

### Phase A — safe free baseline
- Keep Flutter Android as the first working client.
- Keep FastAPI local-only until PostgreSQL and authentication are implemented.
- Add a provider registry with `rule_based` as the only enabled provider.
- Make capability discovery honest: generation and cloud rendering remain false until tested.
- Preserve local media editing and export paths.

### Phase B — free cloud foundation
- Add a web frontend and deploy its static build to Cloudflare Pages.
- Migrate SQLite schema/data access to PostgreSQL and deploy the API to Render Free.
- Add Supabase authentication and ownership checks.
- Add R2 object storage with signed uploads/downloads.
- Add deployment smoke tests for health, auth, project CRUD, and storage.

### Phase C — resilient media workflows
- Keep heavy media processing on the client where feasible.
- Use database-backed jobs for short server tasks.
- Do not claim reliable background processing on a sleeping free web service. A separate always-on worker or GPU worker requires a confirmed free allocation.
- Add resumable uploads, file quotas, cleanup, and export validation.

### Phase D — optional open-model inference
- Benchmark each model against available compute before enabling it.
- Record model license, source, hardware, native resolution, frame rate, runtime, and memory requirements.
- Enable only genuinely free compute or community grants.
- Clearly distinguish native model output from upscaled output.
- Keep text rendering (especially Arabic RTL) deterministic in the editor/render pipeline.

## 6. Free-tier guardrails

- No paid subscriptions or paid API keys required for normal app operation.
- No automatic upgrades or paid fallback.
- No credit card requirement should be assumed away; provider signup and age/eligibility rules still apply.
- Show a visible quota/capability status and explain when a service sleeps, pauses, or reaches a limit.
- Provide export/download of project metadata so the user can leave a free host without losing work.
- Back up project metadata; object storage is not a backup by itself.
- Keep a local/offline mode so temporary hosting outages do not block editing.

## 7. Current implementation status

This document is a target architecture, not proof of deployment. At the time it was added:
- FastAPI + SQLite project CRUD and deterministic draft planner exist.
- No public authentication, PostgreSQL adapter, R2 integration, web frontend deployment, or production worker exists.
- Image/video generation and multi-track cloud rendering are not connected.
- Do not publish the current unauthenticated API to the public internet.
